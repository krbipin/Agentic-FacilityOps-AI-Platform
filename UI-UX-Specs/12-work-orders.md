# Work Orders
- **Route:** /work-orders
- **Page type:** management (app shell)
- **Primary agent:** Maintenance Agent (generates), Alert & Automation Module (tickets)
- **Data source:** MAINTENANCE_RECORDS, ASSETS, ALERTS

## Vibe & Purpose
Operational ticket queue for maintenance. Technicians and dispatchers create, assign, prioritize, and track work orders — many auto-generated by the Maintenance Agent from predicted failures. Status-driven board with clear SLA urgency.

**PLATFORM:** Web, Desktop-first (responsive to Mobile/Tab)

**PAGE STRUCTURE:**
1. **Topbar:** facility selector, live clock, alert bell `4`, theme toggle, user menu.
2. **Sidebar:** Overview, Energy, Maintenance, Occupancy, Security, Cost, Intelligence, Alerts, Reports, Assets, Work Orders (active), Copilot, Settings.
3. **Primary Content Area:**
   - **Page header:** "Work Orders" + subtitle "89 tickets · 12 predicted failures flagged" + "New work order" primary button + "Auto-create from predictions" toggle.
   - **Status summary cards (4):** Open `24` (red) · In Progress `18` (blue) · Scheduled `15` (amber) · Completed `32` (green).
   - **Kanban board (3 columns):** Open | In Progress | Completed (Scheduled merged into Open on mobile). Cards draggable between columns.
     Card fields: ticket ID (mono), asset name, issue type, priority chip, source ("AI-predicted" violet tag / "Manual"), due (mono, red if overdue), assignee avatar initials.
     Sample cards:
     - `WO-1042` · AHU-4 · Vibration excessive · P1 Critical · AI-predicted · Due Today · — unassigned
     - `WO-1041` · Elev-4 · Door sensor fault · P2 High · Manual · Due Today · SM
     - `WO-1038` · Chiller-2 · Refrigerant recharge · P2 High · AI-predicted · Due Aug 06 · JD
     - `WO-1035` · Gen-7 · Bearing inspection · P3 Med · AI-predicted · Due Aug 12 · AP
     - `WO-1029` · VRF-12 · Filter clean · P3 Med · Manual · Done Aug 01 · KS
   - **Work order detail drawer (on card click):**
     - Header: ID, status dropdown, priority, source tag.
     - Description + asset link (jumps to Asset drawer).
     - Assignee selector, due date, estimated hours.
     - **Timeline:** Created (auto by Maintenance Agent 14:30) → Assigned → Started → Completed.
     - **Chat/notes thread:** technician notes + agent notes ("Maintenance Agent: recommend replacing bearing during visit").
     - Actions: Save, Complete, Reopen, Link alert.
   - **Prediction-backed list (bottom):** work orders created from AI predictions with the linked predicted-failure confidence (mono `92%`).
4. **Footer:** System status + SLA compliance `96%`.

**Components & Real Data:**
- 4 status summary cards.
- Kanban columns with drag cards.
- Priority chips: P1 red, P2 amber, P3 blue.
- Source tags: "AI-predicted" violet, "Manual" steel.
- Detail drawer with timeline + notes.
- SLA compliance in footer.

**Interactions:**
- Drag card between columns updates status (optimistic UI + undo toast).
- Card click → detail drawer; status change in drawer syncs board.
- "New work order" → modal: asset picker (searchable), issue type, priority, assignee, due date, source (default Manual).
- "Auto-create from predictions" toggle → generates draft tickets for the 12 predicted failures.
- Assignee initials update on assignment.
- Complete requires a completion note (validation).

**States:**
- Loading skeleton columns; Empty column: "No tickets — drag to rebalance"; Error banner; offline → board read-only.
- Overdue cards get red due + pulse.

**Responsive Behavior:**
- **1280px+:** 4 summary cards; 3-column kanban; drawer right.
- **768px:** kanban becomes 3 horizontal columns with horizontal scroll (sticky column headers); summary 2×2.
- **360px:** kanban collapses to a single stacked list with status as a chip on each card; drawer full-screen sheet; "New work order" sticky bottom.
